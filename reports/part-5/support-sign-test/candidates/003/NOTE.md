The harness now resolves an order without a number only when the customer’s product wording matches exactly one order on their account; otherwise it asks for the order number. This should fix the missing-order-number refund failures and lets the same lookup answer shipping and refund status questions without issuing a refund. The existing refund policy and supervisor approval flow still apply, and retries recover the original receipt instead of recalculating the refund. No model call was added, and evaluation was not run.
