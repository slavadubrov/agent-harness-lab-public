# Part 4: saved runs for the evaluator

`RESULTS.md` is generated by `make part4-regrade` from the files in this folder. Nothing
in it calls a model.

| Folder | What it holds |
| --- | --- |
| `known/<spec>/r01..r10/` | 10 runs of each design on the 16 known tasks |
| `new/<spec>/r01..r05/` | 5 runs of each design on 32 new messages the designs were not written for |
| `labels/` | 60 replies with labels, used to measure the judge and the held-reply check |
| `frontier-*.svg` | Success with the judge against cost per task and against p95 latency, with intervals on both axes |
| `failures-*.svg` | Where each design fails, graded with the judge: tasks by kind of check, or tasks by run |

Each run folder has `results.jsonl` (one row per task), `traces.jsonl` (every message,
model call, tool call and event), `run.json` (spec, prices, package versions, commit) and
`judge.jsonl` (the judge's reading of each reply).

## How these runs were made

All runs used `openai/gpt-6-luna` on OpenRouter's OpenAI endpoint with fallbacks off, on
2026-10-15, at the commit recorded in each `run.json`. The designs' runs were
interleaved: run 1 of every design before run 2 of any. Dollars use the price table the
Part 3 runs recorded (2026-10-05); the live prices on 2026-10-15 were the same. Chat
calls' computed cost equals the cost OpenRouter billed; the judge's and the router's
TypeSafe Jev calls are computed only.

The folders are named by spec: `a3-do-nothing` is design 0, `a1-plain` design 1,
`a2-agent-approval` design 2, `a2-workflow` design 3, `a2-router` design 4 and `a2-code`
design 5. `a3-hybrid` is a prototype that routes known kinds of request to code and the
rest to an agent. Its runs are here because 10 of the 60 labelled replies are its
replies; its spec and code are not in this repository, and `RESULTS.md` leaves it out.
The email address that one of the 32 messages asks to switch to is `ben@ortiz.example`,
a reserved example domain.

## Limits

- One chat model, one endpoint, one day. 10 runs of 16 tasks and 5 runs of 32 messages.
- The 32 new messages and the expected outcome of every task were written by Claude and
  approved by the author before any of these runs. The outcomes of the 16 known tasks
  were written after the Part 3 runs.
- The database checks of these runs ran in the runner's process, next to the harness.
- Each labelled reply's label was written by Claude before the judge version it measures
  ran. No person has reviewed them yet (see `labels/README.md`).
